# 可编辑页面 viewer：方案分析 v0.1

日期：2026-10-22。决策建议：本地浏览器编辑器作为工作入口，原页图像与结构化文字分层保存；先实现固定页对照，Typst 或 LaTeX 作为按需导出层。本文保留初期方案分析。当前实现已扩展至第 60、90–99、140、220 页；PDF 导出使用 viewer 同一套排版坐标，不另经 Typst/LaTeX 重排。2026-10-22 按用户要求改为无品牌、无装饰的简洁界面。

## 用户提出的两个问题

整页图像生成把识字、翻译、排版和绘图合在一次不可控的输出中。改单字可能需要重新生成文字区域甚至全页，既可能改错其他字，也可能改变照片细节。因此应把 AI 用在识别结构、生成译文和提出版面建议上，最后由确定性的排版程序画字。

“格式文本”也不应退化成一份按行串接的 Markdown。复杂图文书需要保存标题、正文、侧栏、图片、图注、列表、表格、阅读顺序、坐标及它们之间的关系。编辑器和排版器可以复用这些结构，但没有工具能仅从错误 OCR 自动恢复原来的出版工程文件。

这本 PDF 的直接证据是：每页主要为一张整页 JPEG；272 页中有 25 页没有文字层，已有 OCR 存在词内空格和日文误识。其版式并不是一组能直接修改的 PDF 文本框。第 60 页是正文和双照片，第 140 页有侧栏和截图，第 220 页有英日图文和列表，三页适合用作不同版式的验收样本。

## 推荐的三层结构

1. **证据层**：原 PDF、逐页扫描、原 OCR 和定位框。只读，不覆盖。
2. **内容与布局层**：按稳定段落 ID 存放英/日校订原文、中文、术语链接、译注、版本及 source regions；另存中文目标布局 target frame、字号、样式和图层顺序。
3. **展示层**：同一份内容生成对照阅读、原位中文叠加，以及重排导出。修改文本后重新渲染相应块，必要时重排其所属页；不用生成新的照片。

原文的证据框与中文的目标文本框必须分开。中文扩写后移动的是目标框，不应把引用证据的坐标一起移动。一个段落可关联多个原页区域，也可在导出中产生多个文字框。字号、缩放、段落拆分均需保留映射。

## Viewer 怎样编辑

实际界面使用顶部页码选择和少量操作控件，书页占主要区域；一次只编辑一个段落。宽窗口在右侧编辑，窄窗口在整页下方编辑，不保留装饰导航栏、品牌或卡片。点击原页中的区域定位对应段落，点段落则高亮原图。中文预览可以与原页并排，也可叠加于原位；显示未译、待校、已审、溢出等状态。

核心操作是编辑段落、调整阅读顺序、拖动/缩放译文框、绑定图注、查术语、比较修订。先用文本字段与受控样式满足需求，确实需要行内样式时再引入富文本编辑器；不要让任意 HTML 成为数据母版。

保存应落到本地 JSON 文件或本地数据库并可导出 JSON；第一版建议按页 JSON，便于 Git 差异和备份。浏览器 localStorage 只适合临时恢复，不应作为唯一存储。更改文本记录 content_revision，更改布局记录 layout_revision；两类修改可分别撤销。

## 如何处理复杂排版

### A. 原页 + 对照模式：第一版默认

完整保留扫描页，中文放在旁边，与区域互相定位。页面复杂也不妨碍学习：暂时没有结构化的图表仍可放大阅读，之后逐块补齐。无需等 272 页全部复原才能开始翻译。中文可以自然伸长；原书页码作为引用锚点保留，中文阅读页不必一一同页。

### B. 原位中文叠加模式：逐页可选

底层是原页，文字区域上方加可撤销遮罩及真实可选中的中文字层。照片和截图作为锁定区域，保持原图；纯色纸面可以用相应背景遮罩。遇到纹理、渐变、文字压图、弯曲扫描或框线穿过文字时，简单白框会破坏背景，这些块标记为需要人工修复或继续采用旁栏翻译，不承诺全页自动擦字。

遮罩和文字框都存坐标，不把译文烧录到图片。原文始终可切回。SVG 可承担区域选框和控制柄，HTML 文字层承担排版与编辑；Canvas 适合显示页面，但单独使用 Canvas 会增加选字、输入法、搜索和可访问性的实现负担。

文字溢出处理顺序：重新换行 → 调整允许范围内的间距/字号 → 扩展目标框、移动后续块 → 转为对照或续页。设最低可读字号；不自动缩到看不清，不删除内容。页面完整性检查要结合实际浏览器尺寸测量，不能只按字符数猜测。

### C. 结构化重排模式：后续导出

将常见版式归为几个模板：单栏正文、正文加侧栏、成对英日截图与共享图注、列表/表格、章扉页。图注与图片组成不可随意拆散的块；侧栏通过正文锚点定位，避免漂到无关段落。罕见页保留手工覆盖配置，不为每页写完全独立的模板。

重排允许页数变化，保留“原书第 X 页”的映射。若要求中文严格维持 272 页，译文长度会成为硬约束，人工微调成本明显提高；因此目前不以逐像素或逐页等长复刻作为验收目标。

## 工具比较

| 方案 | 对本项目的价值 | 主要代价 | 建议角色 |
| --- | --- | --- | --- |
| HTML/CSS + SVG 交互层 | 点击即改、可选字、拖框、双语对照、术语提示 | 固定分页和打印输出需要额外验证 | 首选编辑和阅读界面 |
| PDF.js | 浏览器内渲染原 PDF、缩放及坐标转换 | 不会自动把扫描书变成可编辑文字；重写内容需另做 | 原页渲染备选；第一版也可直接用页 JPEG |
| Typst | grid、place、页面样式可表达模板和定位布局 | 依然需要版面结构与溢出处理；不自带所见即改交互 | 优先评估的排版导出器 |
| LaTeX | 成熟的书籍结构、多语言和高质量 PDF 排版 | 图片、旁注、浮动、绝对定位混用时需要模板；拖动界面与源码映射另做 | 熟悉 TeX 或重视印刷排版时采用 |
| AI 直接生成译页 | 快速看嵌字效果 | 难做精确文字修改，图片可能变化，缺可编辑文本 | 可选视觉草稿 |

LaTeX 能完成复杂排版，但不是“识别扫描后自动恢复书页”的工具，也不是一个现成的可视化页面编辑器。可以做“编辑文本/坐标 → 生成 .tex → 编译 → PDF 预览”的 viewer，但每个拖动、改字和定位都仍需要映射层。对于目前反复校订的学习流程，这条路线比 HTML 编辑层多了一段编译与映射工作。

Typst 有网格及绝对定位能力，因而值得作为导出候选；这属于工程选择判断，不是已测试其对本书优于 LaTeX。两者都应由同一份结构化内容生成，不建立必须手动同步的第二份译文母稿。普通 Markdown 可作为阅读导出，但不足以单独记录全部位置和关联。

## 最小验证范围与验收

只实现第 60、140、220 页，不先做全书通用自动复原：

1. 修改任意中文段落后立即看到更新，保存、关闭、重新打开后仍在。
2. 原图可切回，源图哈希不变；照片不经过图像生成。
3. 点击原文与译文能相互定位；缩放后选择框仍对齐。
4. 将一段译文扩展 50% 后能提示溢出，并允许扩框或转对照；没有遮住照片或隐藏尾句。
5. 能表达第 140 页的侧栏/截图关联、第 220 页的日文与中文释义；保留日文、大小写与专名。
6. 改动原文或术语决议后，相关译文被标记待复核。
7. 输出一个可选中文字的本地 PDF，并检查换页、字体与图片完整性；不把仅能编译当作排版合格。

## 私人项目与 AI 数据流

当前维持本地 Git，无远程、无 Pages。后续若建立 GitHub 远程，必须为 private，不配置公开发布；本次没有创建远程。源码和小型文字数据可本地版本管理，PDF、原扫描、缓存与生成图片留本地备份，避免把 330 MB PDF 和重复位图塞进每次历史。

私人仓库不等于离线 AI。原页发送到 GPT 等服务会发生远程处理；viewer 的本地阅读编辑功能应不依赖在线服务，模型调用独立、可选择发送范围，并记录调用。术语下载也与书籍内容上传分开。本次只检索公共资料，没有新增发送书页给模型的调用。

## 现行格式与导出实现（2026-10-22）

每页为 UTF-8 JSON，`schema_version: 2`；页面按稳定块 ID 保存。一个块对应一个可独立编辑和定位的标题、段落、引文、侧注、图注或列表。第 90 页表格每格为独立块，第 92/97 页列表逐项成块，第 93 页引文框内的段落独立保存，通过 `structure` 关联：table-cell 的 group/row/column/header、list-item 的 group/index、callout 的 group。旧第 220 页双栏日文列表保留原来的单块多行结构。

主要字段：

| 字段 | 含义 |
| --- | --- |
| pdf_page / printed_page | PDF 页序与纸面页码，分别保存 |
| revision / updated_at | 整页修订号及 UTC 更新时间，用于乐观锁，当前不拆为内容/布局两个版本 |
| reference_size | 屏幕排版参考尺寸，统一高度 1400，单位为 CSS 像素 |
| physical_size_pt | 原 PDF 页面尺寸，点；导出保持该尺寸 |
| image_url / image_sha256 / raw_ocr_ref | 本地扫描图及只读证据引用；旧三页的 OCR 位置由页码推导 |
| blocks[].source | 校订原文、语言、证据框 bbox 与独立的擦字框 mask_bbox；不可由载入操作改写 |
| blocks[].translation | text、status、spans；真正可编辑的译文母稿 |
| blocks[].layout | bbox、font_size、line_height 倍数、font_weight、text_align，可选颜色、手工断点与不可拆短语 |
| blocks[].calibration | 人工校准基准，“还原位置”读取此处 |
| blocks[].notes / structure | 译注与结构关系；当前存档保留，载入不重建页面结构 |

`bbox=[x0,y0,x1,y1]` 是 0–1 归一化页坐标，原点左上。布局字号以 reference_size 的 CSS 像素计，导出乘页面尺寸比例，不直接将 20px 当成 20pt。

行内格式保存示例：

```json
{"text":"游戏 Undertale 的译名","status":"draft","spans":[{"start":3,"end":12,"italic":true,"lang":"en"}]}
```

start/end 为 UTF-16 代码单元偏移，左闭右开，避免 JavaScript 与 Python 对补充平面字符计数不同。范围必须有序、不重叠、落在完整 Unicode 字符边界上。lang 支持 zh-Hans/en/ja；italic 为 true/false。正文纯文本不含 HTML，自动换行不写进 text；用户输入的换行保留其意义，`layout.break_after` 仅用于特定图注的校准断点。当前 UI 提供行内斜体，块级字体和字号由排版规则控制；不是任意富文本编辑器。

JSON 导出包为：

```json
{"format":"undertale-study","version":1,"created_at":"UTC 时间","book":{"source_sha256":"原 PDF 的 SHA-256"},"pages":["完整的页对象"]}
```

上例 pages 是示意，实际为对象数组。导出不包含图片、字体或原 PDF；同项目可完整恢复译文及布局。未知包版本、不同书籍、重复/缺失块 ID、改写原文和无效坐标等均拒绝。当前是恢复既有页的存档格式，不是批量新增页的导入协议。

读取：校验包版本和原书哈希 → 对照现有页面及只读结构 → 校验文字、格式范围、样式与坐标 → 显示载入预览 → 再核对修订号 → 备份全部受影响页 → 事务式写入。中途磁盘失败回滚；进程意外退出留下 pending 日志时，下次启动恢复备份。载入不会执行脚本或 HTML，也不会依据导入路径读写任意文件。

PDF 导出：先保存编辑 → 用页面同一个渲染器在固定尺寸下排版 → 测量每个中日字及英文词的位置/基线/字体 → 检查溢出、框重叠、修订号和逐字完整性 → ReportLab 在原扫描及独立遮罩上绘制嵌入字体的 Unicode 文字。拉丁词使用 HarfBuzz shaping；字体各个静态字重有独立 PostScript 名称。浏览器排版快照保存在导出旁，便于复查。打印标记、装订出血、重排长文和 PDF/A 不在当前导出范围。


## 对齐、段落接排及语言呈现：已选方案

排版与语言呈现方案（2026-10-22）

已决定：按用途区分原文与译文；名字和语言分析对象优先保留。用户已选择该方案。

1. 文本框、段落与区域
改宽时固定左沿/中心/右沿是几何锚点，与文字本身的左齐/右齐不同。左侧边注默认固定右沿，右侧边注默认固定左沿，图注默认中心，正文默认左沿。修改 X 或宽度接近同类同侧框或校准边缘 4 个参考像素以内时吸附，显示临时辅助线；可以关闭。原文擦字框独立，始终不跟着移动。

目前段间距不匀主要因为固定框高度留白、下一段又固定起点，并不只是译文有空行。方案是保留稳定的段落 ID，在有限的图文区域内接排：下一段 Y = 上一段实际文字高度的底部 + 段距。字体、缩进、双语引文仍可每段独立，点击原文定位不丢失。比把整页合成一个字符串更容易处理图片、表格和原文映射。

已实现“高度随文字”“接在段后”“段距”“区域底线 Y”，第 94 页的两组正文—引文—正文使用 12px 段距试排。区域底线是接排的允许范围，超出显示警告并拒绝 PDF 导出；不会挤掉图片，也不会自动缩字。首尾多余换行可显式清除；内部换行继续保留诗行/对照行含义。整页不自动串成一个流，图片、列表圆点、气泡边框仍是固定障碍。

2. 引文和语言例子的统一规则
普通叙述/访谈：中文为主。引号或缩进本身不决定要不要双语。
语言分析对象：保留被分析的词形、大小写、标点、原语例句，同时给可见的简短中文释义。
英日版本比较：每一侧保存自己的原语与中文释义，分别标记“英文版”“日文版”；不能把两侧都替换成中文后仍标“英文/日文”。
作者用英文解释日文时：标记“日版大意（作者英文转述）”，不得把英语当成日文原句，不从英语反造日文。
仅给罗马字时：保留读音并配中文意义；没有核实的日文表记留空，不根据读音猜汉字。
名字：保留名字，不强行按普通词译义。只有本段分析名字来源时才添加相应意义与出处。

例：COOL DUDE（酷哥）／イカした こうげき（ikashita kōgeki；很酷的攻击）。二者是版本对应关系，不声称逐词等义。
例：yūrei（心怀怨恨或仍有遗憾的死者之魂）。该处原书只提供罗马字时不补造日文写法。

3. 原语、读音、释义、说明分开保存
建议语言条目结构：id、role、language、original、source_kind、reading、gloss_zh、note_zh、source_ref、status。source_kind 至少区分 verbatim / romanization / author_gloss。reading 不是译文；gloss_zh 是让人看懂的最短中文；note_zh 承担词源、双关、适用语境等长解释。

普通正文首次在独立阅读单元（本页或本节）出现的非专名外语词给简短释义；同单元重复可以省略括注，但条目仍可点按。承载论证的词义必须可见，不只藏进悬停。必需释义放不下时换成下行释义、独立对照块或续页，不删释义、不无限缩字。

注释定位使用稳定 block_id + 原文字串 + 前后文 + 修订号，偏移仅作加速。编辑后文字不再匹配就标“待重新关联”，不默默挂到另一个同名词。借鉴 W3C 的 TextQuoteSelector 思路，不宣称当前文件已实现完整 Web Annotation 标准。

4. 悬停与 PDF
网页适合：虚线下划线提示，悬停或键盘聚焦显示，点击固定，Esc/关闭按钮隐藏，触屏可点按，指针移到注释内容上仍保留。不能只有 title 气泡或只有鼠标入口。已制作独立交互样张。
PDF 支持 Text/Popup 等注释，Acrobat 还提供悬停提示选项；阅读器决定呈现方式，因此不能保证浏览器预览、手机和打印都出现相同悬浮框。已制作标准 PDF 文字注释样张，无 JavaScript；第二页有相同内容的可打印注释。建议正式输出采用“可见短释义 + 可点击注释 + 可打印注释页”，弹出层是补充入口。
本次没有在所有 PDF 阅读器实测悬停行为；样张的注释对象和中文内容已做结构检查。不要把文件中存在 /Annots 等同于每个阅读器交互都已通过。

5. 斜体与原始文本
现有 JSON 是 text + spans，spans 的 start/end 是 UTF-16 偏移，italic/lang 分开存；所以文本框看不到星号。斜体不是临时靠关键词猜出来的效果。原三页曾由默认词表决定，已经迁移成显式 spans。
需要可见标记，但不把整个复杂书页降成 Markdown。已增加“格式标记”查看，显示 *Undertale* 等斜体和语言列表；编辑仍使用正文选区和“斜体”按钮。它是只读投影，不是第二份可独立改写的母稿。将来增加可编辑标记模式时，必须先保证与 spans 双向无损、转义星号、跨段格式和日语标签都不丢失，再开放。

6. 预案与验证效率
保留：独立固定框、限定区域内段落流、表格单元格、列表、引文框、图注与图片关联。更复杂的竖排、文字压图、非矩形环绕、跨页续段，允许页面专属配置及“原图+对照/续页”回退；不承诺一个模板自动复原全书。
下一阶段将图片和框线显式标为 protected_regions，区域之间声明阅读顺序。当前底线由人工设置，只保护这条线以下；尚不是自动识别全部图片的碰撞引擎。
验证按修改影响范围执行：改一个块先测该块及其接排后继；改断行/字体时测代表性混排页；导出比较文字完整性和实际坐标；只有批量交付或全局排版变化才逐页校样。不得每次改一个按钮又把所有 PDF 重新渲染。

## 2026-10-23 正式注释实现（替代此前“尚未接入”的阶段说明）

每个 block 新增 annotations 数组。每条包含 id、anchor、original、reading、gloss_zh、note_zh、language、source_kind、role、source_ref、status。anchor 包含 quote/prefix/suffix/start/end/status；UTF-16 偏移与 JavaScript 选区一致，前后文各最多 24 个 Unicode 字符。整段关联用空 quote。失联状态需用户显式重新关联。

页面 schema_version=3，存档 version=2。写入字段严格校验、同块 ID 不重复、来源及原文仍不可覆盖；新版存档缺少 annotations 时拒绝载入。旧版存档没有注释字段时保留当前注释，避免静默丢失。删除需在新版存档明确给出空数组。

网页注释命中区域独立叠在书页上，未插入正文字符或改变断行；导出的正文与浏览器仍共用坐标。PDF 从服务端当前注释数据生成附件，正文数字及往返链接独立于正文文本；不接受客户端任意改写注释内容的 PDF 快照。当前导出的页数包含注释附页。

不包含多用户协同编辑或图像内文字 OCR 注释。注释可以关联现有段落或其中的文字；截图保持原图。

## 2026-10-23 居中、底线与 PDF 导出校准

框内标题按原图实际内栏（横线端点）居中，resize_anchor 同步 center，不能拿英文 OCR 字宽当作标题栏宽度。本轮修正35处。标题底线必须核对浅灰细线，不使用下方截图黑边；本轮对照原图应用75页86条标题修正，不修改翻译。

33处装饰引号保留原扫描像素；source.quote_mark 的 bbox 定义原图裁片，offset 定义相对文本框偏移。网页与 PDF 都跟随实际接排位置放置，引号与文本遮罩独立。原书图像、raw OCR 不变。

排版检查以浏览器 Range 与 Canvas 实际字形度量为准，不再用 scrollHeight 或整块行盒重叠判定。自然斜体侧伸按字体实际侧边留白处理，显示层不裁去笔画；auto_height 框按可用区域底线与实际字面碰撞检查，固定框另查字面边界。仍不等于自动识别全部图片碰撞。

原生中英混排的可断行点和正文排版使用同一套禁则，通过 wbr 明确标记，避免窄栏引号、英文、括注连成过长一组。PDF 保存浏览器实际行内坐标，正常英文跨行分成对应行的文字 run，不再拒绝导出。

导出预检一次收集所选页面全部实际问题；保存版本冲突与排版问题分别提示。全书 PDF 请求上限128MiB，其他写入仍16MB；仅本地会话令牌与原有 Origin 限制下可用。
